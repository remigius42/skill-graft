# AGENTS.md

skill-graft builds a user's agent skills from other people's repositories: it computes the transitive hull of
the skills they ask for, vendors and patches them (renames included), and hands the result to
[APM](https://github.com/microsoft/apm) to deploy. Read `CONTEXT.md` (glossary; use its terms) and `docs/adr/`
before changing behavior. Until OpenSpec specs cover it, `docs/design.md` holds how it works.

## Git

- Conventional Commits (commitlint). No Co-Authored-By trailer.
- Local only: there is no remote. Never add one or push without asking.
- Work on a branch, never on main: one per OpenSpec change, `feat/opsx-<change-name>`.

## Workflow

- Changes go through OpenSpec: propose (proposal, design, specs, tasks), wait for approval, then apply
  test-first (red-green-refactor), one commit per task.
- `pre-commit run --all-files` stays green at every commit. New words: add them, sorted, to `words` in
  `.cspell.yaml`.
- `.claude/` is generated by `openspec init`. Regenerate it rather than editing it.

## Python

- Python 3.11 or later, for `tomllib`. Runtime dependencies: the standard library and `tomlkit`, nothing else.
  Call `git` and `apm` as subprocesses; never import `apm_cli`, whose internals are not an API.
- `mypy --strict` and `ruff` run as pre-commit hooks, configured in `pyproject.toml`.

## Tests

- Never touch the real `~/.apm`, `~/.claude`, or `~/.agents`. Anything that runs `apm` sets `HOME` to a
  temporary directory.
- Fixture skills and source repositories are synthetic, built in the test. Do not copy real skills into the
  repository.
